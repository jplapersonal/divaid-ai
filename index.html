The Paradigm Shift

Like a Blockchain for AI Operations

Traditional LLM inference requires a single, monolithic GPU holding the entire model in VRAM. Divaid completely shatters this assumption using Pipeline Parallelism.

Think of it like a blockchain network: millions of miners don't solve the entire cryptographic chain at once. They process tiny, discrete chunks of work that mathematically chain together.

  • 1

    Sharded Weights: The LLM is sliced layer by layer. Each Access Point in your ceiling holds only a microscopic fraction of the model.

  • 2

    Discrete Computation: An AP receives a hidden-state tensor, performs matrix multiplication using its local layer, and transmits the resulting tensor to the next AP.

  • 3

    The Network is the Bus: Utilizing Cisco's ultra-low latency mGig backplane, tensor passing (barely ~4KB of data) happens in microseconds.

The Technical Bottleneck

The Magic: Beating the 100MB IOx Limit

Cisco CW917X Access Points possess incredibly capable quad-core ARM64 processors. However, Cisco Application Hosting (IOx) restricts Docker containers via cgroups to roughly 100MB of RAM. A modern LLM simply cannot fit.

Here is how we solved the mathematically impossible.

01

Model Selection

We start with a highly optimized Small Language Model (SLM) such as Meta's Llama-3.2-1B. At FP16 precision, this model weighs around 2.2 Gigabytes.

02

GGUF Quantization

We apply INT4 GGUF (Q4_K_M) quantization. By compressing the weights to 4 bits, the total model footprint is drastically reduced from 2.2GB down to roughly 800MB with near-zero perplexity degradation.

03

Layer Slicing

The Llama-3.2-1B model is composed of 16 Transformer Layers. We split the 800MB model horizontally into 16 discrete chunks.

800MB ÷ 16 Layers = ~50MB per AP.

50MB < 100MB IOx Threshold. Success.

Execution Pipeline Details

Deep dive into the routing and computation mechanics deployed across the Cisco fabric.

Orchestrator Node (Catalyst)

The Cisco Catalyst Switch (e.g., 9300X/9400) acts as the swarm master. It hosts the Tokenizer, the immense Embedding Table lookup, and the final LM Head. When a prompt is received, it converts text to tokens, fetches the 4096-dimensional embedding vectors, and transmits the initial tensor to the first AP over gRPC.

Worker Nodes (CW917X APs)

Each AP runs a highly stripped-down inference engine written in C++ (ggml-based). Upon receiving a tensor via its wired mGig connection, it computes Attention and Feed-Forward Network (FFN) logic for its specific layer. It maintains its own local subset of the KV Cache to support generation.

100% Air-Gapped Data Sovereignty

No APIs to the cloud. No subscriptions. The data never leaves the VLAN. The models are loaded directly into the network hardware. Perfect for defense, highly secure manufacturing, or isolated financial branches.
