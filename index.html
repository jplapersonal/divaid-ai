The Mathematical Breakthrough

How we bypass the strict 100MB RAM limit of Cisco Application Hosting (IOx) containers on Access Points.

Pipeline Parallelism on the Edge

Cisco APs (like the CW9178) have capable ARM64 processors but strict `cgroups` limiting IOx containers to ~100MB RAM. An entire LLM cannot fit.

Our approach: We utilize Pipeline Parallelism. We take a modern SLM (e.g., Llama-3.2-1B), apply 4-bit GGUF quantization reducing it to ~800MB, and slice its 16 Transformer layers. Each AP acts as a single-layer processor.

  • Memory Footprint: 1 Layer = ~50MB. Fits safely under the 100MB IOx limit.
  • Network Latency: Passing the hidden state tensor (4KB) between APs via the Catalyst switch backplane takes <0.1ms per hop.
  • Scale: 16 APs can run a 1 Billion parameter model. A standard school or office with 150 APs becomes a massive parallel compute swarm.
